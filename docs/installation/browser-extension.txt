DIGITALPULSE __BROWSER__ EXTENSION - INTERNAL TEST BUILD

1. Extract digitalpulse-__SLUG__-extension.zip to a permanent user folder.
2. Open __EXTENSIONS_PAGE__ in __BROWSER__ and enable Developer mode.
3. Select Load unpacked and choose the extracted digitalpulse-__SLUG__-extension
   folder containing manifest.json (not the ZIP or its enclosing downloads folder).
4. Open the Extensions menu and pin DigitalPulse to the toolbar.
5. Sign in to DigitalPulse Employee Setup with your own employee account, read
   the privacy disclosure, and provide explicit consent if you agree. Consent,
   administrator authorization, an active account, and a valid schedule/time zone
   are separate server requirements; installation does not enable monitoring.
6. Choose Browser extension in Employee Setup and generate a one-time token.
   It expires after four hours and may enroll only one installation. Use a
   separate token for each Chrome or Edge browser profile. Never share tokens.
7. Open the DigitalPulse popup and verify the administrator-configured backend.
   For a new installation only, paste the token and
   select Enroll. The token is cleared after success; it is not saved in settings.
8. Click Sync Now or reopen the popup to check its authenticated heartbeat.
   Backend Online means the API is reachable. Device Connected requires an
   authenticated heartbeat. Monitoring can remain paused even while connected.
9. Return to Employee Setup to see backend device and monitoring status. A
   download or a locally marked installation start never proves enrollment.
10. Read Optional browser screenshots in the popup. Only if you agree, click
    Allow scheduled browser screenshots and accept the browser's own prompt.
    Scheduled capture requires the broad all-websites host permission;
    activeTab cannot authorize unattended alarms. Declining keeps screenshots off.
    Turn off browser screenshot permission in the popup to revoke it.
11. Browser permission does not replace employee acknowledgement, organization
    authorization, device assignment/selection, consent or monitoring schedules.
    Screenshot capture requires the extension to be pinned and its ON badge
    established. Only the active HTTP(S) tab in a focused normal window is
    eligible, never incognito, background, internal or minimized tabs.
    ON means authorized, not successfully uploaded. Popup connection status is
    heartbeat/domain activity status, not screenshot authorization.

UPDATING AN EXISTING INSTALLATION
Update the SAME permanent unpacked folder and use Reload. Do not uninstall,
change its path/profile, or clear extension storage. Check that extension ID and
Device ID remain unchanged. Enrollment credentials are not changed by this update.

PRIVACY AND CREDENTIALS
The extension records foreground website domains and active durations only while
server authorization is valid. It pauses outside assigned hours, without consent
or administrator approval, or when authorization expires. Optional authorized
screenshots contain visible page contents and may include sensitive information.
Images remain in memory only and authorization is rechecked before upload to
private backend storage under organization retention rules. Failed images are
discarded; retries take a new authorized image. The activity queue is retained
when sync is denied or offline. No keystroke or clipboard collection is added.
The device secret is stored in extension-local storage, accessible to trusted
extension contexts only, and is never displayed in the popup or dashboard.
Do not export the browser profile or extension storage to another employee.

BACKEND SETTINGS
The backend address is generated by administrators when packaging the extension.
HTTP is permitted only for loopback development. Remote origins require HTTPS
and approval for that exact host. Paths, embedded credentials, queries and
fragments are rejected. An enrolled device or pending queue cannot be redirected
to a different backend; ask an administrator to plan migration and revocation.
The extension never discards the pending queue when saving a backend setting.

TROUBLESHOOTING / REMOVAL
Offline: check the configured backend's /api/v1/health endpoint is up.
Token rejected: generate a fresh Browser extension token for this account.
Paused: review consent, administrator authorization, account status and schedule.
No activity: verify the current tab is an HTTP(S) site during authorized hours.
Stop collection by disabling the extension. Before removing it, review pending
events and revoke the device in DigitalPulse. Removing a browser extension can
delete its local storage/queue; it does not delete PostgreSQL records.

RUNTIME VERIFICATION REQUIRED
Test actual permission denial, grant, removal, capture and gallery delivery in
both browsers before distribution. Server withdrawal is learned at policy refresh
and again before upload. Alarms may be delayed during suspension; explicit
deadline checks prevent expired capture/upload. Cancellation cannot retract bytes
already sent. Backend authorization remains authoritative.
